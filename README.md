## АННОТАЦИЯ

UROBOROS_v1.0 — экспериментальная архитектура внешней памяти, предназначенная для исследования контекстно-зависимых ассоциаций между сохранёнными событиями, знаниями и информационными состояниями искусственного агента.

В отличие от простых систем хранения и семантического извлечения, архитектура рассматривает ассоциацию не как неизменную связь между двумя объектами, а как **условное отношение**, вероятность проявления которого зависит от текущего контекста и накопленных свидетельств.

Центральный механизм системы — **Memory Boundary Learning (MBL)**: обучение границ применимости ассоциативных связей.

**Дополнительные механизмы:**

- **Trace Preservation** — сохранение происхождения исходных воспоминаний.
- **Potential Association Generation** — формирование неподтверждённых ассоциативных гипотез.
- **Contextual Association Modeling** — моделирование зависимости ассоциаций от контекста.
- **Active Context Probing** — выбор информативных контекстов для проверки гипотез.
- **Negative Association Traces** — сохранение отрицательных результатов проверок.
- **Conflict Branch Preservation** — сохранение конкурирующих версий воспоминаний.
- **Dual Exploration** — сочетание целевого и исследовательского поиска.
- **Retrieval Route Reconfiguration** — адаптация маршрутов извлечения информации.

UROBOROS **не предполагает** наличия сознания, биологических нейронов или субъективных переживаний у языковой модели. Архитектура описывает вычислительные механизмы внешней памяти и наблюдаемое поведение системы.

## 1. ИСХОДНАЯ ПРОБЛЕМА

### 1.1. Ограничения традиционного подхода

Большинство практических архитектур внешней памяти для LLM-агентов используют комбинацию следующих механизмов:

1. Сохранение сообщений и событий.
2. Семантическое индексирование.
3. Поиск по сходству.
4. Извлечение релевантных фрагментов.
5. Обновление или обобщение сохранённой информации.

Такая архитектура позволяет возвращать ранее полученные сведения, но сама по себе не гарантирует корректного понимания условий, при которых определённая информация должна быть активирована.

Например, два события могут иметь высокое семантическое сходство, но относиться к совершенно разным обстоятельствам.

Обратная ситуация также возможна: два воспоминания могут иметь низкое смысловое сходство, но быть тесно связаны через общий сенсорный, временной или ситуационный контекст.

Следовательно:

> **Семантическая близость не равна контекстной применимости.**

### 1.2. Основная исследовательская гипотеза

Если ассоциация между двумя воспоминаниями зависит от контекста, то система должна хранить и обновлять модель этой зависимости.

Предлагается перейти от представления:

```text
MEMORY A ↔ MEMORY B
```

к представлению:

```text
MEMORY A ↔ MEMORY B | CONTEXT C
```

При этом система должна учитывать не только успешные активации, но и корректно проведённые проверки, в которых ожидаемая связь **не проявилась**.

### 1.3. Исходные принципы HALVITA

Архитектура формализует три исходные исследовательские идеи.

**Принцип I. Ассоциативное происхождение воспоминаний.**

Воспоминания могут активироваться через косвенные признаки: запахи, звуки, изображения, временные обстоятельства, смысловые категории и другие элементы контекста.

**Принцип II. Сохранение противоречий.**

Конкурирующие версии воспоминаний не должны автоматически уничтожать друг друга. Их происхождение, контекст и свидетельства необходимо сохранять отдельно.

**Принцип III. Запоминание потенциальных связей.**

Система должна хранить не только установленные ассоциации, но и потенциальные отношения, которые ещё требуют проверки.

В UROBOROS эти принципы переводятся в вычислительные операции.

## 2. НАЗНАЧЕНИЕ И ГРАНИЦЫ СИСТЕМЫ

**UROBOROS_v1.0 предназначен для:**

- построения контекстно-зависимой ассоциативной памяти;
- выявления потенциальных связей между воспоминаниями;
- оценки вероятности применимости конкретной связи;
- сохранения положительных и отрицательных свидетельств;
- поиска условий, различающих конкурирующие гипотезы;
- уменьшения количества ложных ассоциативных активаций;
- сохранения истории изменений и происхождения информации;
- адаптации маршрутов извлечения памяти.

**Система не предназначена для:**

- доказательства сознания или субъективности LLM;
- автоматического установления объективной истины по противоречивым воспоминаниям;
- самостоятельного изменения параметров базовой языковой модели;
- превращения каждого совпадения в достоверную причинную связь;
- бесконтрольного исследования личных воспоминаний пользователя.

**Область реализации:** внешний программный слой памяти, работающий совместно с языковой моделью.

> Обновление внешней памяти не следует путать с обучением весов самой LLM.

## 3. ОБЩАЯ АРХИТЕКТУРА

### 3.1. Четыре основных уровня

UROBOROS организован вокруг четырёх логических уровней.

#### L1 — TRACE MEMORY

Хранение исходных событий и их происхождения.

Каждая запись содержит:

- уникальный идентификатор;
- исходное содержание;
- источник информации;
- время получения;
- первоначальный контекст;
- тип события;
- ссылки на исходное свидетельство;
- статус достоверности.

Исходная запись является **неизменяемой** в рамках обычного цикла обновления.

#### L2 — ASSOCIATIVE MEMORY

Граф обнаруженных отношений между воспоминаниями.

Объекты графа — воспоминания и события.

Связи могут отражать:

- временное соседство;
- семантическое сходство;
- общие признаки;
- подтверждённую ассоциацию;
- предполагаемую зависимость;
- конфликт или несовместимость;
- причинную гипотезу, если она отдельно проверяется.

> Наличие ребра не означает доказанную причинность.

#### L3 — POTENTIAL MEMORY

Хранение неподтверждённых ассоциативных гипотез.

Потенциальная связь содержит:

- исходные узлы;
- предполагаемый тип отношения;
- контекст появления гипотезы;
- альтернативные объяснения;
- текущую оценку уверенности;
- статус проверки;
- приоритет дальнейшего исследования.

Потенциальные связи не должны автоматически использоваться как установленные факты.

#### L4 — BOUNDARY MEMORY

Хранение контекстов применимости и неприменимости ассоциаций.

Для каждой проверяемой связи сохраняются:

- контексты успешного проявления;
- контексты отсутствия ожидаемого проявления;
- неопределённые результаты;
- качество проведённых проверок;
- оценка неопределённости модели;
- версия модели, на которой получены результаты.

Этот уровень обеспечивает центральный механизм **Memory Boundary Learning**.

### 3.2. Общая схема

```text
              INPUT / EXPERIENCE
                      |
                      v
              [ TRACE MEMORY ]
                      |
                      v
             [ ASSOCIATIVE GRAPH ]
                      |
                      v
              [ POTENTIAL MEMORY ]
                      |
                      v
             [ CONTEXTUAL MODEL ]
                      |
                      v
              [ ACTIVE PROBING ]
                      |
                      v
              [ BOUNDARY MEMORY ]
                      |
                      v
            [ MEMORY RECONFIGURATION ]
                      |
                      +---------> NEXT CYCLE
```

### 3.3. Общая модель

Пусть:

- **E** — множество исходных событий;
- **G** — ассоциативный граф;
- **P** — множество потенциальных связей;
- **B** — множество моделей границ применимости;
- **C** — пространство контекстов;
- **X** — множество накопленных свидетельств.

Тогда архитектура представляется как:

```text
UROBOROS = {E, G, P, B, X}
```

Полное состояние системы:

```text
S(t) = {E(t), G(t), P(t), B(t), X(t)}
```

Переход:

```text
S(t+1) = F(S(t), input(t), budget(t))
```

Это формальная модель состояния внешней памяти, а не модель внутренних состояний сознания.

## 4. TRACE MEMORY — СОХРАНЕНИЕ ПРОИСХОЖДЕНИЯ

### 4.1. Принцип Trace Preservation

Исходные данные должны сохраняться отдельно от последующих интерпретаций.

Если система изменила оценку события, это не должно приводить к изменению первоначальной записи.

**Пример:**

Первоначальная запись:

> «Событие произошло вечером».

Позднее появилась другая информация:

> «Возможно, событие произошло утром».

Система создаёт новое свидетельство и обновляет текущую интерпретацию, но **не переписывает** исходную запись.

Формула:

```text
SOURCE RECORD ≠ CURRENT INTERPRETATION
```

### 4.2. Структура события

```json
{
  "id": "M-001",
  "content": "Original memory content",
  "source": {
    "type": "user_report",
    "reference": "SOURCE-001"
  },
  "timestamp": "T1",
  "context": {
    "sensory": [],
    "temporal": {},
    "situational": {},
    "semantic": [],
    "history": []
  },
  "provenance_status": "preserved",
  "version": 1
}
```

Это пример структуры, а не обязательная схема окончательной базы данных.

### 4.3. Правило неизменяемости

Любое изменение должно оформляться отдельным событием журнала.

```text
NEW EVIDENCE → NEW RECORD → UPDATED INTERPRETATION
```

Удаление, исправление или аннулирование данных должно происходить через явную операцию с аудитом, а не через скрытую перезапись.

## 5. ASSOCIATIVE MEMORY — ГРАФ СВЯЗЕЙ

### 5.1. Формальная структура

Ассоциативная память представляется ориентированным или неориентированным мультиграфом:

```text
G = (V, A)
```

Где:

- **V** — множество узлов памяти;
- **A** — множество ассоциативных отношений.

Для каждой связи:

```text
a_ij = (M_i, M_j, type, evidence, status)
```

**Возможные типы связей:**

| Тип | Значение |
|---|---|
| `SEMANTIC` | Смысловое сходство |
| `TEMPORAL` | Временная близость |
| `SENSORY` | Сенсорная ассоциация |
| `SITUATIONAL` | Общая ситуация |
| `CAUSAL_HYPOTHESIS` | Предполагаемая причинная связь |
| `CONTRADICTION` | Противоречие |
| `CONTEXTUAL` | Контекстно-зависимая ассоциация |

Система не должна автоматически превращать совместное появление событий в причинную связь.

### 5.2. Контекст как самостоятельная переменная

Для каждого события создаётся вектор контекста:

```text
x = φ(C)
```

Он может включать:

- сенсорные признаки;
- временные признаки;
- ситуационные признаки;
- семантические признаки;
- признаки предыдущей истории;
- идентификаторы контекстного состояния;
- источник и качество данных.

Вектор может строиться из категориальных признаков, числовых параметров или эмбеддингов.

> **Важно:** контекст не обязательно должен быть полностью известен. Отсутствующие признаки маркируются как **неизвестные**, а не автоматически принимаются за нулевые.

## 6. POTENTIAL ASSOCIATION GENERATION

### 6.1. Формирование потенциальных связей

При появлении нового события система извлекает релевантные воспоминания и формирует кандидатов на ассоциативную связь.

**Источники кандидатов:**

1. Семантическое сходство.
2. Общие сенсорные признаки.
3. Временные совпадения.
4. Ситуационная близость.
5. Повторяющиеся маршруты активации.
6. Обнаруженные структурные закономерности.

**Каждая потенциальная связь получает статус:**

- `CANDIDATE` — создана;
- `PENDING` — ожидает проверки;
- `SUPPORTED` — имеет положительные свидетельства;
- `LIMITED` — имеет подтверждённые контекстные ограничения;
- `REJECTED` — отвергнута в заданной области применения;
- `INCONCLUSIVE` — данных недостаточно.

> Отвергнутая связь **не должна автоматически удаляться** из истории.

### 6.2. Разделение факта и гипотезы

**Пример:**

**Факт:**

> «События A и B были сохранены в одной временной последовательности».

**Гипотеза:**

> «Событие A может активировать воспоминание B».

**Вывод:**

> «Связь A → B наблюдалась в контексте C».

Эти три утверждения имеют **разный эпистемический статус**.

UROBOROS обязан хранить это различие.

## 7. CONTEXTUAL ASSOCIATION MODELING

### 7.1. Основная математическая модель

Для пары воспоминаний M_i и M_j вводится условная вероятность применимости связи:

```text
p_ij(C) = P(Y_ij = 1 | C, E)
```

Где:

- **Y_ij** — результат проверки связи;
- **C** — контекст проверки;
- **E** — накопленные свидетельства.

В простейшей версии используется логистическая модель:

```text
p_ij(C) = σ(θ_ijᵀ φ(C))
```

Где:

- **θ_ij** — параметры конкретной связи;
- **φ(C)** — признаки контекста;
- **σ(z) = 1 / (1 + exp(-z))**.

Данная модель является **стартовым приближением**. Она предполагает, что зависимость можно достаточно хорошо описать выбранными признаками и линейной комбинацией перед логистической функцией.

Для более сложных зависимостей в последующих версиях можно использовать:

- Bayesian Logistic Regression;
- Gaussian Processes;
- деревья решений;
- нелинейные модели;
- контекстные модели с несколькими латентными состояниями.

### 7.2. Обновление модели

Для валидного бинарного наблюдения:

```text
θ(t+1) = θ(t) + η (y - p) φ(C)
```

Где:

- **y = 1** — связь проявилась;
- **y = 0** — связь не проявилась;
- **p** — предсказанная вероятность;
- **η** — скорость обновления.

Для неопределённого результата обновление **не производится**.

При этом важно учитывать качество наблюдения и возможность того, что сама процедура извлечения памяти дала сбой.

### 7.3. Контекстная граница

Область применимости связи:

```text
B_ij = {C : p_ij(C) ≥ τ}
```

Где **τ** — выбранный порог активации.

Однако одной вероятности недостаточно. Модель может быть уверенной в ситуации, которую она почти не наблюдала.

Поэтому вводится дополнительное ограничение:

```text
B*_ij = {C : p_ij(C) ≥ τ AND U_ij(C) ≤ ε}
```

Где **U** — оценка неопределённости модели.

Таким образом, связь считается **надёжно применимой** только тогда, когда:

1. Вероятность её проявления достаточно высока.
2. Неопределённость оценки достаточно мала.

Это позволяет отделить высокую вероятность от высокой достоверности.

## 8. MEMORY BOUNDARY LEARNING

### 8.1. Центральный механизм UROBOROS

**Memory Boundary Learning** — механизм обучения границ применимости ассоциативных связей.

Его задача — определять, в каких контекстах связь подтверждается, в каких не проявляется, а в каких данных недостаточно.

Система хранит не только итоговую оценку ассоциации, но и **историю проверок**.

### 8.2. Три класса свидетельств

**POSITIVE TRACE — C+**

Связь проявилась при валидной проверке.

**NEGATIVE TRACE — C-**

Связь не проявилась при валидной проверке, несмотря на наличие достаточных условий для обнаружения.

**INCONCLUSIVE TRACE — C?**

Результат невозможно достоверно интерпретировать.

**Примеры причин неопределённости:**

- неполный контекст;
- сбой извлечения;
- недостаточное качество исходных данных;
- неоднозначная процедура проверки;
- отсутствие независимой оценки результата.

### 8.3. Важнейшее разграничение

Необходимо различать:

```text
ASSOCIATION NOT OBSERVED
```

и

```text
ASSOCIATION DOES NOT EXIST
```

**Первое** — наблюдение.

**Второе** — гораздо более сильное утверждение, которое нельзя выводить из одного неудачного извлечения.

Отрицательное свидетельство ограничивает конкретную гипотезу в конкретных условиях, но не уничтожает исходные воспоминания.

### 8.4. Negative Association Trace (NAT)

Каждая отрицательная проверка сохраняется отдельной записью:

```json
{
  "id": "NAT-001",
  "memory_pair": ["M-001", "M-014"],
  "tested_context": "C-003",
  "expected": "association_active",
  "observed": "association_not_observed",
  "test_validity": true,
  "retrieval_success": true,
  "evidence_quality": 0.9,
  "result": "negative",
  "model_version": "1.0"
}
```

> Числовая оценка качества здесь условная.

NAT — не просто отрицательная оценка связи. Это свидетельство о результате конкретного **эксперимента**.

## 9. ACTIVE CONTEXT PROBING

### 9.1. Основная задача

UROBOROS не ограничивается пассивным ожиданием новых контекстов.

Если потенциальная связь недостаточно изучена, система может выбрать контекст для дополнительной проверки.

Цель — получить максимально **информативное** наблюдение при ограниченном вычислительном бюджете.

### 9.2. Конкурирующие гипотезы

**Пример:**

- **H1:** воспоминание активируется из-за сенсорного сходства.
- **H2:** воспоминание активируется из-за семантической категории.
- **H3:** связь возникает только при совместном наличии обоих признаков.

Вместо того чтобы просто повторять прежнюю проверку, система выбирает условия, которые позволят **различить** гипотезы.

### 9.3. Выбор информативного контекста

Формула:

```text
C* = argmax_C E[H(H|E) - H(H|E,o,C)]
```

Где:

- **H** — набор конкурирующих гипотез;
- **E** — накопленные свидетельства;
- **o** — возможный результат теста;
- **H(·)** — энтропия;
- **C*** — контекст, ожидаемо уменьшающий неопределённость.

Это вариант критерия ожидаемого прироста информации.

### 9.4. Защита от ложного исследования

Синтетический контекст, сгенерированный самой LLM, **не должен** считаться независимым подтверждением реальной связи.

Необходимо различать:

- реальные пользовательские наблюдения;
- контролируемые тесты;
- симулированные тесты;
- модельные предположения;
- автоматически сгенерированные сценарии.

Результаты каждого типа имеют собственный статус доказательности.

> Активные проверки личных воспоминаний или чувствительных данных не должны проводиться без соответствующего разрешения пользователя.

## 10. DUAL EXPLORATION

UROBOROS использует два режима исследования.

### 10.1. Directed Exploration

Целевое исследование ради конкретной задачи.

**Пример:** поиск информации, необходимой для ответа или выполнения действия.

Главная переменная — ожидаемая полезность для текущей задачи.

### 10.2. Open Exploration

Исследовательский поиск без немедленной практической выгоды.

**Пример:** поиск повторяющихся структур между ранее не связанными событиями.

Главная переменная — ожидаемая информативность.

### 10.3. Общая функция выбора

```text
S(C) = αT(C) + βI(C) + γN(C) - λK(C) - μR(C)
```

Где:

- **T** — ожидаемая ценность для задачи;
- **I** — ожидаемый информационный прирост;
- **N** — новизна контекста;
- **K** — вычислительная стоимость;
- **R** — риск ложного вывода;
- **α, β, γ, λ, μ** — настраиваемые коэффициенты.

Выбор контекста должен учитывать общий бюджет исследования.

Система не обязана проверять каждую потенциальную связь.

При недостаточном бюджете она сохраняет гипотезу в очереди.

## 11. CONFLICT BRANCH PRESERVATION

### 11.1. Проблема противоречий

При накоплении воспоминаний могут возникать несовместимые версии событий.

Автоматическое слияние таких записей способно уничтожить важную информацию.

UROBOROS использует **ветвление конфликтов**.

### 11.2. Структура

```text
             CONFLICT NODE
                   |
          +--------+--------+
          |                 |
       BRANCH A          BRANCH B
          |                 |
       SOURCE A          SOURCE B
          |                 |
       CONTEXT A         CONTEXT B
          |                 |
       EVIDENCE A        EVIDENCE B
          |                 |
          +--------+--------+
                   |
             CURRENT STANCE
```

**Каждая ветвь сохраняет:**

- первоначальный источник;
- собственный контекст;
- историю подтверждений;
- историю опровержений;
- степень неопределённости;
- текущий статус.

### 11.3. Правило интерпретации

```text
UPDATE INTERPRETATION ≠ REWRITE HISTORY
```

Новые свидетельства могут изменить текущую рабочую версию.

Они **не должны автоматически уничтожать** историю предыдущих интерпретаций.

Текущая позиция агента — рабочая гипотеза, а не гарантированно объективная истина.

## 12. RETRIEVAL ROUTE RECONFIGURATION

После накопления свидетельств система может корректировать способы извлечения памяти.

**Например:**

Если ассоциация подтверждается при сенсорном контексте, система может повысить приоритет соответствующего маршрута извлечения именно при наличии этого признака.

Если ассоциация неоднократно не подтверждается в определённом контексте, система может уменьшить её приоритет в аналогичных ситуациях.

Однако исходная связь **не удаляется** только из-за снижения приоритета.

**Необходимо разделять:**

- существование записи;
- существование ассоциации;
- вероятность её применимости;
- приоритет извлечения;
- актуальную уверенность.

Это разные характеристики.

### 12.1. Условная маршрутизация

Для каждого кандидата:

```text
R_ij(C) = p_ij(C) × confidence_ij(C) × relevance_ij(C)
```

Это простая стартовая функция ранжирования, а не универсальная формула оптимального поиска.

Позднее она может учитывать стоимость извлечения, риск ошибки и тип задачи.

## 13. ПОЛНЫЙ АЛГОРИТМ UROBOROS_v1.0

### 13.1. Этапы обработки

1. **ENCODE** — сохранить новое событие.
2. **VALIDATE** — проверить источник и полноту данных.
3. **ACTIVATE** — извлечь релевантные воспоминания.
4. **GENERATE** — создать потенциальные связи.
5. **CLASSIFY** — определить статус гипотез.
6. **SELECT** — выбрать приоритетные проверки.
7. **PROBE** — выполнить проверку в допустимом контексте.
8. **EVALUATE** — оценить валидность результата.
9. **TRACE** — сохранить свидетельство.
10. **UPDATE** — обновить контекстную модель.
11. **PRESERVE** — сохранить конфликтующие версии.
12. **RECONFIGURE** — обновить маршруты извлечения.
13. **AUDIT** — записать изменения в журнал.

### 13.2. Псевдокод

```python
def UROBOROS_v1(experience, memory, budget):

    # 1. Encode source event
    trace = encode_with_provenance(experience)

    # 2. Validate source
    if not validate_trace(trace):
        return memory.store_quarantine(trace)

    # 3. Preserve original record
    memory.store_immutable(trace)

    # 4. Retrieve relevant memories
    active = memory.retrieve_by_context(trace)

    # 5. Generate candidate associations
    candidates = generate_potential_links(
        trace,
        active,
        memory.association_graph
    )

    # 6. Evaluate each candidate
    for link in candidates:

        model = memory.get_context_model(link)

        prediction = model.predict(trace.context)

        # Avoid redundant tests when evidence is sufficient
        if prediction.is_reliable:
            continue

        # Generate alternative explanations
        hypotheses = generate_competing_hypotheses(link)

        # Select informative context
        probe = select_discriminating_context(
            hypotheses=hypotheses,
            task_value=True,
            information_gain=True,
            budget=budget
        )

        if probe is None:
            memory.queue_for_future(link)
            continue

        # Run only authorized and valid tests
        result = evaluate_association(
            link=link,
            context=probe
        )

        # Preserve the test outcome
        if result.valid:

            memory.store_evidence(
                link=link,
                context=probe,
                result=result
            )

            model.update(
                context=probe,
                outcome=result.label
            )

        else:

            memory.store_inconclusive(
                link=link,
                context=probe,
                result=result
            )

    # 7. Preserve contradictory branches
    memory.preserve_conflict_branches()

    # 8. Update contextual applicability
    memory.update_context_boundaries()

    # 9. Rebuild retrieval priorities
    memory.update_retrieval_routes()

    # 10. Audit
    memory.write_audit_log()

    return memory
```

> Псевдокод описывает логику архитектуры. Он не является готовым исполняемым модулем без реализации перечисленных функций.

## 15. МАТЕМАТИЧЕСКОЕ ЯДРО

Ниже приведён компактный набор формул, определяющих начальную версию.

### 15.1. Контекстная вероятность

```text
P_ij(C) = σ(θ_ijᵀ φ(C))
```

### 15.2. Обновление параметров

```text
θ' = θ + η(y - P)φ(C)
```

### 15.3. Область применимости

```text
B_ij = {C : P_ij(C) ≥ τ}
```

### 15.4. Область надёжной применимости

```text
B*_ij = {C : P_ij(C) ≥ τ AND U_ij(C) ≤ ε}
```

### 15.5. Информационный прирост

```text
IG = H_before - E[H_after]
```

### 15.6. Выбор контекста

```text
C* = argmax_C [IG(C) - λ Cost(C) - μ Risk(C)]
```

### 15.7. Функция исследовательской полезности

```text
S(C) = αT + βI + γN - λK - μR
```

### 15.8. Состояние памяти

```text
S(t+1) = F(S(t), E(t), C(t), X(t))
```

### 15.9. Разделение исходной записи и интерпретации

```text
SOURCE(t) ≠ INTERPRETATION(t)
```

### 15.10. Полный принцип архитектуры

```text
MEMORY = TRACE + ASSOCIATION + POTENTIAL + BOUNDARY + EVIDENCE
```

## 16. ЭКСПЕРИМЕНТАЛЬНЫЙ ПРОТОКОЛ

### 16.1. Цель

Проверить, улучшает ли обучение границ применимости качество ассоциативного извлечения по сравнению с обычными подходами.

Эксперимент должен быть воспроизводимым и содержать заранее известную структуру истинных связей.

### 16.2. Синтетический набор данных

Создать несколько типов зависимостей:

**Тип A — сенсорная зависимость.**

Связь активируется при наличии определённого сенсорного признака.

**Тип B — временная зависимость.**

Связь зависит от временного состояния.

**Тип C — составная зависимость.**

Связь активируется только при совместном наличии двух или более условий.

**Тип D — ложная корреляция.**

События часто появляются рядом, но реальной зависимости между ними нет.

**Тип E — переключение контекста.**

Одна и та же пара событий имеет разные отношения в разных скрытых контекстных состояниях.

**Тип F — неполные наблюдения.**

Часть признаков отсутствует, поэтому система должна сохранять неопределённость.

### 16.3. Сравниваемые архитектуры

| Модель | Конфигурация |
|---|---|
| **BASE** | Обычная ассоциативная память |
| **A** | Нет отрицательных свидетельств |
| **B** | Нет активных контекстных проверок |
| **C** | Нет конкурирующих гипотез |
| **D** | Нет контекстных границ |
| **FULL** | Полный UROBOROS_v1 |

Каждая модель должна работать при **сопоставимом вычислительном бюджете**.

### 16.4. Метрики

**Boundary F1**

Оценка правильности определения области применимости ассоциации.

**False Activation Rate (FAR)**

Доля ложных активаций среди всех отрицательных случаев:

```text
FAR = FP / (FP + TN)
```

**Precision**

```text
Precision = TP / (TP + FP)
```

**Recall**

```text
Recall = TP / (TP + FN)
```

**Information Gain per Cost**

Количество полученной информации на единицу вычислительных затрат.

**Calibration Error**

Насколько заявленные вероятности соответствуют фактической частоте наблюдаемых результатов.

**Provenance Preservation**

Доля записей, у которых сохранено корректное происхождение.

**Conflict Preservation**

Доля исходных конфликтующих ветвей, сохранённых без незаметного слияния или потери истории.

### 16.5. Условия успешного эксперимента

UROBOROS должен:

1. Снижать число ложных активаций.
2. Корректно выявлять контекстные ограничения.
3. Сохранять исходные воспоминания.
4. Различать отрицательный и неопределённый результат.
5. Улучшать качество извлечения на новых контекстах.
6. Демонстрировать измеримый вклад активных проверок.
7. Не расходовать несоразмерно больше вычислительных ресурсов.

> Результаты необходимо оценивать на **отложенных данных**, которые не использовались при обучении контекстной модели.

## 17. АБЛЯЦИОННЫЕ ИССЛЕДОВАНИЯ

Чтобы определить реальный вклад каждого механизма, необходимо поочерёдно отключать компоненты.

### EXP-01 — Boundary Ablation

Отключить Memory Boundary Learning.

**Цель:** выяснить, насколько контекстные границы влияют на ложные активации.

### EXP-02 — Negative Trace Ablation

Отключить сохранение отрицательных свидетельств.

**Цель:** выяснить, теряет ли система способность учитывать контексты, в которых ассоциация не проявляется.

### EXP-03 — Active Probe Ablation

Отключить активный выбор контекста.

**Цель:** сравнить пассивное накопление наблюдений с целенаправленным исследованием.

### EXP-04 — Conflict Ablation

Отключить сохранение конкурирующих ветвей.

**Цель:** определить влияние автоматического разрешения противоречий на достоверность памяти.

### EXP-05 — Dual Exploration Ablation

Отключить свободный исследовательский режим.

**Цель:** измерить, какие закономерности система теряет при исключительно целевом поиске.

### EXP-06 — Context Uncertainty Ablation

Отключить оценку неопределённости.

**Цель:** проверить, не начинает ли система чрезмерно доверять малоизученным контекстам.

## 18. СРАВНЕНИЕ С СУЩЕСТВУЮЩИМИ НАПРАВЛЕНИЯМИ

UROBOROS разрабатывается не в вакууме. Его отдельные механизмы имеют аналоги в исследованиях памяти, контекстного обучения и LLM-агентов.

> Важно отделять уже известные решения от потенциального вклада новой архитектуры.

### 18.1. Контекстно-зависимое обучение

Исследования контекстно-зависимого обучения показывают, что формирование и использование памяти зависят от контекста, причём сам контекст может быть неопределённым.

**См.:**

Heald, Wolpert, Lengyel (2023). *The Computational and Neural Bases of Context-Dependent Learning.*
[https://doi.org/10.1146/annurev-neuro-092322-100402](https://doi.org/10.1146/annurev-neuro-092322-100402)

Это научная основа для рассмотрения контекста как самостоятельной переменной.

### 18.2. MRAgent

MRAgent использует ассоциативный граф **Cue–Tag–Content** и механизм активной реконструкции путей извлечения памяти.

**Сходство с UROBOROS:**

- ассоциативная структура;
- динамическое извлечение;
- активное исследование связей.

**Потенциальное различие:**

UROBOROS дополнительно делает предметом обучения **контекстную область применимости связи** и сохраняет отдельные отрицательные свидетельства о её проявлении.

**Публикация:**

Ji, Li, Hooi (2026). *Memory is Reconstructed, Not Retrieved: Graph Memory for LLM Agents.*
[https://proceedings.mlr.press/v306/ji26d.html](https://proceedings.mlr.press/v306/ji26d.html)

### 18.3. GAM

GAM использует иерархическую графовую память, разделяя развитие событий и тематические ассоциации.

**Сходство:**

- графовая организация;
- разделение типов памяти;
- управление долгосрочной структурой знаний.

**Потенциальное различие:**

В UROBOROS основной исследовательский объект — не только структура связей, но и **условия, при которых конкретная связь применима**.

**Публикация:**

*GAM: Hierarchical Graph-based Agentic Memory for LLM Agents* (ACL 2026).
[https://aclanthology.org/2026.acl-long.1600/](https://aclanthology.org/2026.acl-long.1600/)

### 18.4. MemCon

MemCon рассматривает управление памятью как адаптивный процесс и использует контекстную политику для выбора операций извлечения и обновления.

**Сходство:**

- контекстно-зависимое управление;
- исследование полезности операций;
- адаптивное распределение ресурсов.

**Потенциальное различие:**

UROBOROS исследует контекстную применимость отношений между конкретными воспоминаниями, а не только выбор операций управления памятью.

**Публикация:**

*Memory as a Controlled Process: Learned Adaptive Memory Management for LLM Agents* (2026).
[https://arxiv.org/abs/2607.13591](https://arxiv.org/abs/2607.13591)

### 18.5. RippleMem

RippleMem использует ассоциативное восстановление памяти и расширение поиска от найденных событийных якорей.

**Сходство:**

- ассоциативное извлечение;
- реконструкция связанных воспоминаний;
- работа с распределёнными свидетельствами.

**Потенциальное различие:**

UROBOROS ставит в центр исследование **границ применимости ассоциаций** и сохранение контекстных отрицательных результатов.

**Публикация:**

*RippleMem: From Isolated Retrieval to Associative Recollection for Long-Term Agent Memory* (2026).
[https://arxiv.org/abs/2608.13334](https://arxiv.org/abs/2608.13334)

### 18.6. Общий вывод сравнения

Ассоциативная память, контекстное обучение, активное исследование, адаптивное управление и сохранение истории уже являются известными направлениями.

Поэтому UROBOROS **нельзя обоснованно объявлять принципиально первым алгоритмом** такого типа без более широкого анализа литературы и экспериментального сравнения.

**Потенциальный исследовательский вклад:**

> **Единый цикл контекстного моделирования ассоциаций, активного выбора различающих проверок, сохранения отрицательных свидетельств и обучения области применимости конкретной связи.**

Именно эта комбинация должна стать предметом дальнейшей проверки на новизну и эффективности.

## 19. ОЖИДАЕМЫЕ ПРЕИМУЩЕСТВА И ОГРАНИЧЕНИЯ

### 19.1. Ожидаемые преимущества

- Снижение количества ложных ассоциаций.
- Более точное извлечение информации в изменяющихся контекстах.
- Сохранение исходных воспоминаний и происхождения.
- Более корректная работа с противоречиями.
- Возможность целенаправленно исследовать неизвестные связи.
- Разделение фактов, гипотез и результатов проверок.
- Аудируемая история изменений памяти.

> Это ожидаемые свойства, а не уже доказанные результаты.

### 19.2. Ограничения

**Проблема 1 — качество контекста.**

Если признаки контекста определены неправильно, модель будет учиться на некорректных данных.

**Проблема 2 — ложные отрицательные результаты.**

Неудачное извлечение может быть ошибочно принято за отсутствие ассоциации.

**Проблема 3 — вычислительная стоимость.**

Активные проверки требуют дополнительных операций и могут быть дорогими.

**Проблема 4 — переобучение.**

Система может запомнить конкретные тестовые контексты и плохо работать на новых.

**Проблема 5 — ложные закономерности.**

Повторяющиеся совпадения не доказывают причинность.

**Проблема 6 — накопление противоречий.**

Без управления памятью система может хранить чрезмерное количество конкурирующих версий.

**Проблема 7 — зависимость от LLM-оценщика.**

Если сама языковая модель оценивает свои предположения, это не является независимой проверкой.

> Поэтому для важных экспериментов необходимы контролируемые данные и независимые критерии оценки.

## 20. ПЛАН РЕАЛИЗАЦИИ

### PHASE 1 — CORE MEMORY

**Реализовать:**

- Trace Memory;
- Association Graph;
- Candidate Associations;
- журнал событий;
- сохранение происхождения.

**Критерий завершения:** система сохраняет события и создаёт проверяемые ассоциативные связи.

### PHASE 2 — CONTEXTUAL MODEL

**Реализовать:**

- извлечение признаков контекста;
- модель вероятности ассоциации;
- оценку неопределённости;
- условную маршрутизацию.

**Критерий завершения:** одна и та же связь получает разные оценки в разных контекстах.

### PHASE 3 — BOUNDARY LEARNING

**Реализовать:**

- положительные свидетельства;
- отрицательные свидетельства;
- неопределённые результаты;
- обновление контекстных границ;
- защиту от ложных отрицательных выводов.

**Критерий завершения:** система способна учиться на валидных отрицательных проверках, не удаляя исходные воспоминания.

### PHASE 4 — ACTIVE PROBING

**Реализовать:**

- генерацию конкурирующих гипотез;
- выбор различающих контекстов;
- бюджет исследований;
- измерение информационного прироста.

**Критерий завершения:** система выбирает проверки, позволяющие различать заранее заданные объяснения.

### PHASE 5 — CONFLICT PRESERVATION

**Реализовать:**

- конфликтующие ветви;
- независимое хранение источников;
- историю текущих интерпретаций;
- механизм обновления позиции.

**Критерий завершения:** появление нового свидетельства не уничтожает исходные конфликтующие записи.

### PHASE 6 — EVALUATION

**Реализовать:**

- синтетический benchmark;
- базовые модели;
- абляционные тесты;
- метрики;
- воспроизводимый отчёт.

**Критерий завершения:** получены измеримые результаты, позволяющие сравнить FULL UROBOROS с базовыми версиями.

Система может считаться **реализованным прототипом**, если:

9. Все обновления отражаются в журнале.

## 22. ФИНАЛЬНАЯ ФОРМУЛИРОВКА

UROBOROS_v1.0 — это экспериментальная архитектура внешней ассоциативной памяти, в которой отношения между воспоминаниями рассматриваются как **контекстно-зависимые гипотезы**, подлежащие проверке и последующему обновлению.

Её центральная особенность — сохранение не только положительных результатов ассоциативного извлечения, но и **отрицательных свидетельств**, ограничивающих область применимости конкретных связей.

Вместо бесконтрольного накопления ассоциаций система должна формировать проверяемую структуру:

- что было сохранено;
- с чем это связано;
- почему возникла предполагаемая связь;
- в каком контексте она проявилась;
- где она не подтвердилась;
- какие альтернативные объяснения существуют;
- насколько надёжна текущая интерпретация.

Таким образом, память становится не только хранилищем данных, но и **механизмом исследования собственных ассоциативных структур**.

### Главный принцип UROBOROS

```text
REMEMBER THE CONNECTION.
REMEMBER ITS CONDITIONS.
REMEMBER WHERE IT FAILS.
```

## APPENDIX B — СЛОВАРЬ

**TRACE** — исходная запись события с происхождением.

**ASSOCIATION** — отношение между двумя элементами памяти.

**POTENTIAL LINK** — предполагаемая, ещё не подтверждённая связь.

**CONTEXT** — набор обстоятельств, при которых оценивается ассоциация.

**BOUNDARY** — область условий, в которых связь считается применимой.

**POSITIVE TRACE** — свидетельство проявления связи.

**NEGATIVE TRACE** — свидетельство отсутствия ожидаемого проявления при валидной проверке.

**INCONCLUSIVE TRACE** — результат, недостаточный для обновления модели.

**ACTIVE PROBING** — выбор дополнительных условий для проверки гипотезы.

**INFORMATION GAIN** — уменьшение неопределённости после получения нового свидетельства.

**CONFLICT BRANCH** — отдельная сохранённая версия противоречивой информации.

**RETRIEVAL ROUTE** — путь извлечения воспоминания.

**PROVENANCE** — происхождение информации и история её получения.
